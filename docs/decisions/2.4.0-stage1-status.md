Resume notes. Nothing here is verified in a render client; "verified" means read from sources or bytecode.

## Step 1 - hooks (written, build pending)

Verified before writing:

- 26.3, all loaders: the sky pass is `SkyRenderer.render(GpuBufferSlice, SkyRenderState)` (Forge and NeoForge
  sources, Fabric bytecode). NeoForge 26.3 calls it only when its `CustomSkyboxRenderer` returned false.
- 26.1.2 and 26.2, all loaders: the pass lambda binds the fog, then calls `renderSkyDisc(I)V` or `renderEndSky()V`
  first, then `renderSunriseAndSunset(PoseStack,F,I)V`, `renderSunMoonAndStars(PoseStack,F,F,F,MoonPhase,F,F)V`,
  `renderDarkDisc()V`, `renderEndFlash(PoseStack,F,F,F)V`. Descriptors read from the Fabric jars' bytecode and the
  Forge / NeoForge sources jars. NeoForge does not patch `SkyRenderer` on these versions; with no custom skybox
  attribute its lambda runs the vanilla calls.
- Decision for NeoForge 26.1.2 / 26.2: the shared mixin, no dimension-type overlays (the attribute id was not
  verified there, and a wrong id breaks the dimension type). `tools/gen_sky_overlays.py` is unchanged.

## Step 2 - 1.21.x

Left on the dimension-type colour floor (no `PlanetSkyDraw` there). Reasons: <=1.21.4 draws in immediate mode
(no RenderPass); 1.21.5 has RenderPass but no DynamicUniforms; 1.21.8-1.21.11 use the blaze3d RenderPass with
DynamicUniforms but different signatures again. Each would be a separate GPU seam that cannot be checked without a
render client.
