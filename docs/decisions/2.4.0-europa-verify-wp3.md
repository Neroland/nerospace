## Checked and OK

- **26.3 codecs (both "not cross-checked" spellings).** `height_range` with `{"type":"minecraft:constant","value":{"absolute":88}}`: `HeightProviderType` registers `constant` with `ConstantHeight.CODEC = VerticalAnchor.CODEC.fieldOf("value")`, and `HeightProvider.CODEC` falls through to the dispatch codec. Valid on 26.3, 26.2 and 1.21.1. Ore target `{"id","properties"}`: `BlockReplacement.CODEC` uses `BlockState.CODEC = either(block id, FULL_CODEC)`, and `FULL_CODEC` dispatches on `id` with a lenient optional `properties`. Valid.
- **26.3 feature and placement types and fields.** `ore` (`targets`/`size`/`discard_chance_on_air_exposure`) and `simple_block` (`to_place`, holder provider; `{"id",...}` objects decode inline via `FULL_CODEC` under `Codec.xor`) are valid. So is `block_column` (`layers[].height` via `IntProviders.NON_NEGATIVE_CODEC`, which accepts `1` and `uniform` with `min_inclusive`/`max_inclusive`; `layers[].provider`; `direction`; `allowed_placement`; `prioritize_tip`). `offset` (`x`/`y`/`z`, int providers in -16..16), `count`, `rarity_filter`, `in_square`, `heightmap`, `height_range`, `environment_scan` (`direction_of_search`/`target_condition`/`allowed_search_condition`/`max_steps` ≤ 32), `block_predicate_filter`, `biome`, and `matching_blocks` (holder set: a single string or a list, with optional `offset`) are all registered and spelled correctly. No 26.3 placed feature uses `random_offset`; the 8 shared `R` placed features that 26.3 inherits use only types that exist on 26.3.
- **26.1.2 / 26.2 (`R` tree).** No `random_patch` type exists (confirmed in `Feature.java`, so deviation 1 is right). `simple_state_provider`, `{"Name","Properties"}` states, `random_offset` (`xz_spread`/`y_spread`, int providers), `uniform` int (`IntProviders` bootstrap) and `block_column` config are all present.
- **1.21.x.** `legacyWorldgen` (`stonecutter.gradle:664-760`) collects only dimension types, dimensions, biomes, noise settings and configured features. It rewrites configured features only for `minecraft:lake` and copies placed features unchanged. Every type and field WP3 uses exists in 1.21.1 and 1.21.4: `ore`, `simple_block`, `block_column`, `simple_state_provider`, `matching_blocks`/`all_of`, `count`, `in_square`, `heightmap`, `random_offset`, `rarity_filter`, `height_range` (`constant`/`uniform`), `environment_scan`, `block_predicate_filter`, `biome`, and `uniform` int. No `trapezoid` is used (1.21.1's `IntProviderType` has none, so the claim holds). Biome `features` pass through untouched.
- **Ids and states.** All 16 referenced blocks are registered in `EuropaContent`. Property names and values exist: `oxidant_ice` `charge` 0..3 (`MAX_CHARGE = 3`), `hydrothermal_vent` `active`, `cryovent` `charged`, `smoker_chimney` `capped` + `waterlogged`, `tube_mat` `waterlogged`. `nerospace:ice_fracture` and `nerospace:hamlet` are registered in both `ModFeatures` branches. Every placed id a biome lists exists, and every placed feature points at an existing configured feature in each tree.
- **Spec 2.7 numbers** match file for file: sizes, counts, rarities, Y ranges (shell ores 104..160/166 inside 101..175; europium -60..-46, rarity 6, size 3, vent fields only; sulfide -60..-24), top-n offsets, cryovent filter, penitente 48 tries with spread 7/2 on `europa_ice`, tube mats 32 tries, and the vent chains with `environment_scan` 32 through water to `vent_basalt`. Generated states: `oxidant_ice[charge=3]`, `hydrothermal_vent[active=true]`, `cryovent[charged=true]`, `tube_mat[waterlogged=true]`, and chimney `[capped=false,waterlogged=true]`×0..2 plus a `[capped=true,waterlogged=true]` tip.
- **Steps and ordering.** Lakes 1, local modifications 2, surface structures 4, ores 6, vegetal 9, matching 26.3 `GenerationStep.Decoration`. Every biome has 11 step lists; `europa_abyss` is empty (`features` []); carvers are empty. The relative order of placed features is the same in every biome that shares them, so there is no feature-order cycle. The biome filter is last in all 14 chains in both trees.
- **Habitat.** Depth at Y 88 is 0.8125, inside `europa_shell` [0.1875, 0.875]. Only `europa_shell` lists it. `StructureSpacing.shouldPlace` gates the count-1 placement.
- **Chaos rafts.** `RaftFallRules.plan` returns none when the group is larger than `CAP` 6 or truncated. Generated chaos ice is a continuous 5-deep sheet on `shell_ice`, and worldgen sends no neighbour updates (`RaftIceBlock` javadoc plus fracture flag 2). Generated rafts never fall.
- **Hazards, end to end.** Surface: `hazard/cold` + `hazard/radiation` tags, frigid band, `RadiationRules.base` = trait 2; `NyxaraCrystalHazards.shaded` reads `#radiation_shade` (which includes `europa_ice`, `chaos_ice` and `shell_ice`), so it gives 1 under a 3-cell roof. Shell, abyss and vent fields: `hazard/cold_mild`, so `frigidCold` is false and any Tier 2 suit shields; radiation base 0. Within 5 of an active vent, or 2 of warm basalt: `ColdShelter` → `EuropaWarmth.scan`, which turns COLD off. The scan covers the radius-5 sphere (515 cells), skips unloaded chunks (`hasChunkAt`), stops at the first hit and is read only when COLD would otherwise bite. The `OxygenHud` change (`client/OxygenHud.java:248-254`) runs only when the first unshielded hazard is COLD, and `shieldedClient` returns false off Europa without reading any block, so other worlds are unaffected. The client cache is keyed on level identity, position and 10-tick bucket. Other planets: `ColdShelterRules.source` gives NONE except Nyxara and Europa. Pinned by `ColdShelterRulesTest`, `HazardModelTest` (existing rows plus Europa rows 154-164) and `RadiationRulesTest.europa`.
- **Hygiene.** No banned word in any Europa worldgen file or the Europa package. Every `europium` mention under `common/src/main` falls on the amendments' WP5 allow-list. All 97 Europa worldgen and tag JSON files parse. The WP3 JSON files use LF. `gen_biome_overlays.py --check` reports "48 ok", `gen_planet_noise.py --check` "437 files, 0 stale", and `gen_sky_overlays.py --check` "8 up to date".
