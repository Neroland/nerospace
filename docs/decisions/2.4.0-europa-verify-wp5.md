- Scope: WP5 (Brinekin villager culture, Star Guide / advancements / gates / quests / meteor materials / compass / demo, gallery and gametest wiring, the `habitats` map layer, the europium easter egg) and the WP4 verifier fixes folded into it (V4-01..V4-04, V4-06, V4-07, V4-09), as claimed in the "## WP5" section of `2.4.0-europa-build-status.md`. Checked against `2.4.0-europa-amendments.md` (authoritative: 3.3 with the V4-01 note, section 7 WP5, F25, F31, F36) and `2.4.0-europa.md` (9.4, 11, 12).
- Date: 2026-11-20
- Verifier: independent agent (did not write WP5). Read-only: no Gradle, no git, generators in `--check` mode only. Vanilla code read from `neoforge/versions/1.21.1/.../neoforge-21.1.265-sources.jar` and `neoforge/versions/26.3/.../minecraft-patched-26.3.0.103-sources.jar`.

## Checked and OK

- **Species ordinal.** `Planet` reads `GREENXERTZ, CINDARA, GLACIRA, NYXARA, EUROPA` (`AlienVillager.java:69-71`). Nothing is reordered and EUROPA is ordinal 4. The renderer switches (`client/AlienVillagerRenderer.java:50-54,75-79,96-100`) are exhaustive with an EUROPA case. `VillagerCultures.ALL` is in ordinal order with BRINEKIN last, and `byLegacy`/`byCulture` round-trip (test `:37-48`). Spawned villagers take the dimension's culture (`:170-174`, `EuropaPlanet` culture `nerospace:brinekin`).
- **Star Guide wire format.** I confirmed the button-id claim: `ServerboundContainerButtonClickPacket.buttonId` is `ByteBufCodecs.VAR_INT` in both 1.21.1 and 26.3, so ids up to 16*16+5 = 261 fit. Data slots stay 16-bit shorts (`ClientboundContainerSetDataPacket` `writeShort`), and the per-chapter mask (6 steps) fits. `DATA_COUNT` = 34. `clickMenuButton` bounds-checks the chapter and step (`StarGuideMenu.java:63-77`). Completion is read live from advancements (`StarGuideProgress`), so there is no new completion store. The only stored state is the existing `star_guide_seen` list, which is padded to the chapter count, has an unbounded codec on all three loaders and is cleared by `NerospaceErasure.java:318`. The test change (`<= 16` to `== 17`, with `<= 16` steps per chapter still asserted) loosens only the safe part. The rail scrolls beyond `RAIL_VISIBLE` (`client/StarGuideScreen.java:80-104`).
- **Star Guide content.** Chapter 16 `worlds_europa` matches design 12.2 exactly (`StarGuide.java:197-206`), with the hidden `rare_earth` step last. `WorldsProgress.WORLDS` gains `europa`. `planet_first_visit` fires generically from `PlanetVisitEvents.onVisit` (`WorldsProgress.java:87-93`), so no roster entry is needed. The weather trial is the generic rule: any non-NONE event under the open sky (`WeatherSurvivalRules.trialActive`), and one `WeatherMachine` carries either Europa event. `totalSteps()` = 45 + 7 x 5 = 80. The hidden step is never hinted (`WorldsProgress.firstOpen`), and the link snapshot omits unearned hidden steps (`link/NerospaceLinkSnapshots.java:433-456`).
- **Advancements (load-time).** `europa.json` is shaped like `mars.json` (`changed_dimension`, parent `nerospace:station`). `worlds/europa/ore.json` uses `inventory_changed` with a valid HolderSet string. `block.json` in `R` (`block_state_property` list) and `R263` (`match_block`) is identical in shape to Mars in each tree. `weather`/`terraform` use `minecraft:impossible`. `europa/rare_earth.json` matches Luna's hidden advancement flag for flag (challenge, hidden, announce, telemetry true, icon `{"id"}`). Every referenced id exists: `nerospace:europa`, `cut_europa_ice`, `deuterium_shard`, `raw_europium`. `legacyAdvancements` (`stonecutter.gradle:615-642`) only rewrites `display.background`, and none of the new files has one, so they pass through unchanged on the 1.21.x nodes, as Mars does.
- **Gates, quests, meteor materials.** The two gate files match the Mars shape. The four quests differ from the Nyxara set only in icon, item and the prospector xp of 250 (design 12.5). They have the same objective and reward types, `mod_hook` gate and `scope: player`. All referenced gates exist and are opened by `WorldsProgress.tick`/`tickWeather`. There are four chapter rows at y 6, and `QuestPackFormatTest` derives its count from `WORLDS.size() * 4`. The meteor materials are shaped like `glacite.json`, and both tiers `rare`/`common` are already in use.
- **Trade table.** `AlienTrades.BRINEKIN_TABLE` (`village/AlienTrades.java:128-146`) matches design 9.4 row for row, and `buy2` argument order matches the Xertz `grav_striders` row. All 13 item ids exist (`assets/nerospace/items/*.json`). `TABLES` has six pairs.
- **Palette and habitat.** `AlienBuild.BRINEKIN` = ice bricks / chaos ice / polished vent basalt / cut ice / sea lantern / tinted glass, in `Palette` field order (`world/AlienBuild.java:34-35,78-84`). `paletteFor` maps `nerospace:brinekin`. `HamletFeature` builds through `SettlementPlacement.begin`, which picks the dimension's culture palette (`world/SettlementPlacement.java:40-51`), so Europa's habitats use it. No sea-lantern or tinted-glass entry is in `#nerospace:europa_heat_sources`. Chaos ice appears only as weathered walls, and its fall rule needs a neighbour update and a group of 6 or fewer.
- **Map layer `habitats` (F25).** It is PROXIMITY via `proximityBuilt`, with icon `id("habitat")` (consistent with the abstract icon ids of the other layers). It is appended last, and the five old ids and scopes are unchanged (test `:185-200`). `query` returns before any proximity layer for an offline viewer or another dimension (`NerospaceMapLayers.java:119-121`). Markers are clipped again by `viewer.within(..., 64)`. The source reads only `getChunkNow` chunks (at most 9 x 9 = 81), keeps no index and stores nothing. Markers carry only the position and culture: no owner, UUID, name or reputation. There is no `getNearestPlayer` in the map code (the only new use is the Vent Ray's flee check, which is behaviour, not authorisation). Lang keys exist for the layer, the marker and all five culture details.
- **Link.** `NerospacePlanets.all()` has 8 entries with EUROPA last. The planet entry is additive, so `SCHEMA_VERSION` 4 unchanged is correct (pinned in `T/link/StarGuideSnapshotCountTest.java:44-49`).
- **Privacy.** `PRIVACY.md:117-121` is accurate against the code: no new store; visits, advancements, gates, Star Guide steps and village reputation gain Europa values; the layer is 64 blocks around you, in your world, position and culture only, and stores nothing. The new logging (`NerospaceDemoModule` outpost warning) names only the world id.
- **Compass.** `europa_compass` is a `DestinationCompassItem` to `ModDimensions.EUROPA_LEVEL` (`nerospace:europa`). It is registered after `RAD_LINING`, is in the creative list and the command list, and has no recipe. `items/`, `models/item/` and the texture are shaped like the other compasses, and the item is in `neroland:highlight/tools`.
- **Wiring.** The demo has 8 outposts, with pad x 4..32 inside the 36-wide footprint. The `europa` `eclipse` sky state exists (`command/GallerySkyStates.java:115-116`), as does the label key. The gallery deck at Y 220 is inside Europa's -64..320 height. The Fabric `WORLDS`/`SHOTS` additions and the `WikiLibrary` `Europa` entry are in place, and `wiki/Europa.md` exists.
- **Test loosenings.** `GuiAssetsTest.ENGLISH_ONLY` holds exactly the two new chapter keys. `DestinationCompassTest.ENGLISH_ONLY` holds only `europa_compass`. Existing keys are still required in `it_it`/`zh_cn`.
- **Easter-egg isolation (F31).** The `EuropiumIsolationTest` allow-list matches amendments section 7 verbatim. It walks `common/src/main`, and its result files show 6 tests, 0 skipped (the `commonMain()` lookup resolves). I re-ran the scan with the same allow-list in Python and found 0 offenders. Exactly the three recipe files mention the element, and nothing under `advancement/recipes/` does. `fabric/src`, `forge/src`, `neoforge/src` and `wiki/` have no mention of the element or the hidden step (only the `tools/` generators, which do not ship). The material highlight tag excludes the element. There is no Luna joke word in any Europa, europium or Brinekin file.
- **V4-01.** Hydrated and living are 0.35 in both trees; rooted is 0.0, and `has_precipitation` is false. `FreezeGuardRules.vanillaTemperature` reproduces vanilla exactly: 1.21.1 `Biome.getHeightAdjustedTemperature` (`y > 80`, `(noise*8 + y - 80) * 0.05/40`) and 26.3 (`snowLevel = seaLevel + 17`, same drop). Europa's `sea_level` is 88 in both trees. The tests fail at 0.2 (`FreezeGuardRulesTest.vanillaHeightRule` asserts 0.2 freezes at Y 176 and 212 on both formulas; `EuropaTerraformTest.seaStaysOpen` reads the JSON). The amendments 3.3 note is present.
- **V4-02.** I recomputed the lattice: 12 passes (x/z stride 2, y stride 3), each capped at the 400 nearest of 432..507 cells. Every cell of the 25 x 9 x 25 box within 12 blocks horizontally is read in exactly one pass, so the search reaches 12 blocks. `keepVent` costs one read per retarget, with `LEASH` 12. `SETTLE_REACH` = 8. A search is at most 400 `isLoaded`-guarded reads.
- **V4-03 / V4-04.** `skaterWalkValue` returns at least 0 over ice, and blades still return -10. `NerospaceEnvironment.at` passes `OxygenManager.noAtmosphere(level)` to the 9-argument `EnvironmentRules.resolve`, and the 8-argument form delegates with false.
- **NOTE fixes.** V4-06: `startSecondaryAtPeak` uses `scaled(...)`. V4-07: the `EuropaHeat` Javadoc now says water fluid tag or brine. V4-09: both comments are reworded.
- **Hygiene.** 2,429 JSON/mcmeta files in the three resource trees all parse, and `en_us.json` has 1,524 keys. `--check` results: `gen_recipe_unlocks` 171 ok; `gen_entity_skins <dir>` 21 of 21; `gen_biome_overlays` 48 ok; `gen_sky_overlays` 8 up to date; `gen_planet_noise` 437 / 0 stale. The test result files show 0 failures and 0 skipped on all nine NeoForge nodes (878 tests, or 883 on the nodes that already carry WP6 tests).

## Verdict

**0 BLOCKER, 0 MAJOR, 0 MINOR, 6 NOTE (V5-01..V5-06).**

WP5 matches the amendments and design 9.4/11/12. Nothing found would fail at load on any cell, change what an existing world loads, or expose personal data. The four WP4 verifier fixes (V4-01..V4-04) and the three NOTE fixes are done as specified, and the V4-01 formulas match the vanilla sources. The notes are optional hardening (stable ordinal fallback, freezing the 2.x Worlds step order) and housekeeping.
