# Nerospace 2.4.0-beta.1 — compliance review (POPIA / GDPR)

Reviewed 2026-11-20 for the sky, shader, ascent and ignition work; extended 2026-11-21 for Europa (see
section 7).

**Result: no open MAJOR, no open MINOR.** No new personal data is collected, stored, sent or logged.

## 1. New data

| Item | Where | Personal data? | Notes |
| --- | --- | --- | --- |
| `AscentHeight` (int) on a rocket entity | entity NBT | No | A config-derived number on a vehicle. Optional key, default 24. |
| Synced ascent duration (int) | entity data, server to client | No | 100 to 240. |
| `rockets.ascentHeight` | server config | No | |
| `sky.bodyStyle`, `shaders.dimensionCompat`, `shaders.drawPlanetSky` | client config, local file | No | Client-side display choices. Never sent to a server or to telemetry. |
| `shaderDimension` on sky profiles | resource pack JSON | No | |

No new `SavedData`, no new per-player record, no new attachment. Nothing to add to
`data.PlayerDataErasure`, and no new row in `PRIVACY.md`.

## 2. Logging

Three log lines are new or moved:

| Line | Arguments | Verdict |
| --- | --- | --- |
| `shader compatibility inactive ({} unavailable)` | one fixed string literal chosen in code | Clean. No pack name, path or version. Logged once per session. |
| `planet sky disabled after a render error` | the exception | Same line and behaviour as 2.3.1 (moved from the NeoForge class into the shared path). The stack trace names classes only. |
| `could not release disabled sky resources` | the exception | As above. |

`ShaderLogScrubTest` pins this: the shader bridge has exactly one log call, every reason passed to it is a
literal, and no log call in the new classes formats in a player name, UUID, position, pack name or path.

The shader bridge reads whether a pack is active and whether the pack names a Nerospace dimension. It
never reads, stores or logs the pack's name or location.

## 3. Telemetry

No new Sentry breadcrumbs, tags or events. Telemetry stays opt-out and scrubbed as before. The shader mod's
presence, the active pack and the three new client settings are not reported anywhere.

## 4. Link module

Unchanged. No new section, field or action; `SCHEMA_VERSION` is not bumped. Scoping stays owner UUID,
member or proximity.

## 5. Third parties

No new dependency. Iris is optional, absent from every loader manifest, reached only by reflection and one
optional mixin, and contributes nothing when it is not installed. No shader pack is bundled, patched or
redistributed. No network access was added.

## 7. Europa

- No new store and no new per-player record. Europa adds values to records that already exist: planet
  visits and first-visit events (Core's anonymous `planet_first_visit` channel), advancements, the two
  Europa progression gates, Star Guide steps, and reputation with Brinekin villagers. These already go
  through the existing erasure and export paths.
- The Habitats map layer is proximity-scoped (village cores within 64 blocks of the online viewer, same
  dimension, loaded chunks only), carries a position and a culture name only, stores nothing and never
  builds a server-wide roster. `PRIVACY.md` gained one paragraph saying so.
- The link module's planet list grows by one entry; no section changed shape, so `SCHEMA_VERSION` is
  unchanged.
- Europa code adds no log lines with player data. Verified independently for each work package (the
  `docs/decisions/2.4.0-europa-verify-*.md` reports).

Result unchanged: no open MAJOR, no open MINOR.

## 6. Checks not possible here

Reading a real client log with a shader pack active was not possible without a render client. The owner's
smoke checklist includes one line for it.
