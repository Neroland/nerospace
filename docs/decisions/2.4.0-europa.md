# Nerospace 2.4.0 — Europa design (build spec)

Written 2026-11-20 against the 2.3.1 tree. Private dev notes; not part of the wiki. No game code or resource
was changed to write this. Companion files: `2.4.0-seams.md` (every seam a world touches), `2.4.0-survey.md`,
and the concept sheets in `2.4.0-europa-concepts/`.

Shorthand: `J` = `common/src/main/java/za/co/neroland/nerospace`, `R` = `common/src/main/resources`,
`R263` = `common/src/main/resources-26.3`, `T` = `common/src/test/java/za/co/neroland/nerospace`,
`E` = `J/world/planet/europa`.

How to read the verification marks: **[read]** = taken from a file I read in this tree; **[design]** = a
decision made here; **[verify]** = the builder must confirm before relying on it (I did not read that code).

Seven things in this document need a small additive Java change outside the Europa package. They are collected
in section 2.3 so they can be reviewed in one place; everything else is new files or list appends.

**Word ban.** The existing isolation tests scan `common/src/main` for the regex `(?<!cave_|sloped_)cheese`.
No Europa Java, JSON, lang or `.mcmeta` file may contain that word. Vanilla noise-router names that start
`cave_` or `sloped_` are exempt by the regex, but do not copy any other vanilla density-function name that
contains the word into `worldgen/**/europa/`.

### 1.3 Clock and day length [design]

Europa is tidally locked, so one Europa day equals one orbit of Jupiter: 3.551 Earth days = 85.2 hours. Mars
already sets the scale at 1 000 ticks per hour (24.6 h → 24 600 ticks), so Europa is **85 200 ticks**, 3.55
Minecraft days, 71 minutes of real time. It sits between Glacira (3 days) and Luna (28).

The clock is a moving one (`dayLengthTicks > 0`): Jupiter is fixed in the sky by the sky profile, not by a fixed
clock. The sun, Io and Ganymede move; Jupiter does not.

Phase convention (shared): 0.00 sunrise, 0.25 noon, 0.50 sunset, 0.75 midnight. On the sub-Jovian side the sun
passes behind Jupiter at noon, so the eclipse is centred on **0.25**.

```java
public static final double PEAK = 0.50;             // a small sun at 5.2 AU, no air to scatter it
public static final double JUPITER_SHINE = 0.06;    // night floor: Jupiter is full at midnight
public static final double ECLIPSE_CENTRE = 0.25;
public static final double ECLIPSE_HALF_WIDTH = 0.035;
public static final double ECLIPSE_START = 0.215;   // must equal sky/europa.json eclipse.phaseStart
public static final double ECLIPSE_END = 0.285;     // must equal sky/europa.json eclipse.phaseEnd
public static final double ECLIPSE_DEPTH = 0.95;
/** Europa crosses Jupiter's magnetotail around the eclipse: the only time a radiation storm may begin. */
public static final double TAIL_START = 0.15;
public static final double TAIL_END = 0.35;

static double daylightAt(double phase) {
    double p = DaylightCurve.wrap(phase);
    double v = DaylightCurve.base(p, 0.03, PEAK);
    v *= 1.0 - ECLIPSE_DEPTH * DaylightCurve.bump((p - ECLIPSE_CENTRE) / ECLIPSE_HALF_WIDTH);
    return DaylightCurve.clamp01(Math.max(JUPITER_SHINE, v));
}

public static boolean inEclipse(double phase) { /* as CindaraPlanet.inEclipse */ }
```

This is the Cindara pattern (`CindaraPlanet.daylightAt`, `ECLIPSE_*`, `inEclipse`) with a night floor like
Glacira's.

**Solar constant.** `SolarAverageTest.averageAtLeastLegacy` loops `Planets.ALL` and requires every planet's
day-average panel factor to be at least 2.0. The curve above averages about 0.26 (half-sine at 0.5, minus the
eclipse notch, plus the floor), so `planetSolar` must be about **8.2**. The builder computes
`SolarMath.dayAverage(Planets.EUROPA, 1.0, 20_000)` and raises the constant in 0.1 steps until it is ≥ 2.0, then
pins it in `SolarAverageTest.constants`. A panel on Europa then peaks at 4.1 for a short day and is nearly dead
for 1.8 Minecraft days of night, which is the intended feel. If the owner would rather have a weak sun
everywhere on Europa, the alternative is to exempt Europa in that test (Q6).

### 4.5 Brine: fluid-like block, not a registered fluid [design]

**Recommendation: `brine` is a `Block`, not a `Fluid`.**

Why a real fluid is expensive here [read: `fluid/ModFluids`, the `FluidFactory` seam]:

- The only fluid in the mod is rocket fuel. It is created through `FluidFactory.INSTANCE.createSource()` /
  `createFlowing()`, which take no argument, so a second fluid means changing a platform seam in all three
  loaders (`AGENTS.md`: "reuse the exact seams; don't add new common interfaces").
- Each loader models fluids differently (NeoForge and Forge `FluidType`, Fabric a fluid class plus a render
  handler), and the 1.21.x cells differ again. That is new per-loader code times three, the one thing the seams
  doc says a world does not need.
- A flowing fluid in brine pockets would drain into every fracture at worldgen and during mining, which is both
  a tick cost and the opposite of "pockets".
- A new fluid also needs fluid tags, pipe and tank handling, and a decision on whether it is "water" for
  drowning, boats and the suit rebreather.

What the block gives instead:

- No collision; `entityInside` applies drag 0.7 and a capped upward push so entities bob, puts out fire, and
  does not count as water (no drowning timer of its own; on an airless world the oxygen system already handles
  breathing).
- Never flows, never freezes (it is not water, so vanilla freezing, `DiamondDustFreeze` and `DryIceRules` never
  see it).
- Picked up and placed by bucket through vanilla `BucketPickup`. Pipes and tanks do not move it; that is
  deliberate and stated on the wiki page.
- Translucent render layer; the model is a full cube with the top face lowered to 14/16 so it reads as a liquid
  surface.

Safe across 27 cells because it uses only `Block`, `BucketPickup` and one overridden method that existing
classes already carry version blocks for.

If the owner wants brine in pipes later, the upgrade path is a real fluid whose bucket and block keep these ids;
the block id `nerospace:brine` would then become the fluid's `LiquidBlock`, so no save breaks (Q8).

### 5.2 How vanilla noise settings produce three layers [design]

`R/data/nerospace/worldgen/noise_settings/europa.json`:

```json
{
  "sea_level": 88,
  "disable_mob_generation": false,
  "aquifers_enabled": false,
  "ore_veins_enabled": false,
  "legacy_random_source": false,
  "default_block": { "Name": "nerospace:shell_ice" },
  "default_fluid": { "Name": "minecraft:water", "Properties": { "level": "0" } },
  "noise": { "min_y": -64, "height": 384, "size_horizontal": 1, "size_vertical": 2 },
  "noise_router": { "…": "see below" },
  "spawn_target": [],
  "surface_rule": { "…": "5.4" }
}
```

With aquifers off, every non-solid cell below `sea_level` is water and every one above is air. So the whole
shape comes from one `final_density`, and the ocean is simply "the hole between two solids, below sea level":

```
final_density = max( seabed , shell − fractures )

seabed   = y_clamped_gradient(−64 → +1.0, −8 → −1.0)  +  0.55 · noise(europa/seabed, xz 1.0, y 0.0)
           // floor between about −44 and −20; basins where the noise is low

shell    = min( underside , topside )
underside = y_clamped_gradient(78 → −1.0, 104 → +1.0)  +  0.45 · noise(europa/underside, xz 0.6, y 0.0)
           // solid above roughly 82..100
topside   = y_clamped_gradient(168 → +1.0, 222 → −1.0) +  surface_shape
surface_shape = spline over the same `erosion` and `ridges` noises the biome source reads:
           plains  : ±0.04  (flat, near 180)
           chaos   : +0.35 · abs(noise(europa/rafts, xz 2.5, y 0.6))   // steep, blocky tilts to ~205
           lineae  : trough −0.12 at |ridges| < 0.02, shoulders +0.10 at 0.02 < |ridges| < 0.06

fractures = 1.2 when abs(noise(europa/fracture, xz 1.8, y 0.08)) < 0.025 and noise(europa/fracture_mask) > 0.35
           // thin, near-vertical sheets because the y scale is tiny; masked so they are occasional;
           // multiplied by y_clamped_gradient(90 → 0, 100 → 1) so they never widen the ocean roof into nothing
```

Consequences worth knowing before building:

- A fracture is air above Y 88 and water below it, so each one is a climbable crack that ends in the sea. That
  is the "fractures leading down" of D19 with no feature code.
- Where the underside noise lifts the roof above 88, the gap is air: a natural under-ice dome with water as its
  floor. The villager habitats use these (9.4).
- Brine pockets are **not** density carving (a carved pocket would be air or sea water). They are an ore-type
  feature that writes `brine` blocks (5.5).
- `tools/gen_planet_noise.py` owns the per-planet noise and density-function files and their `R263` copies; the
  builder adds a Europa spec to it and lets it write both trees. `PlanetNoiseTest` line 54 gets `europa` in its
  roster. The functions above are a specification of shape, not final JSON: the exact amplitudes are tuned in a
  dev client, and the test pins only the invariants in 5.7.
- The `depth` entry of the noise router is replaced by an absolute-height ramp so biomes can be picked by layer:
  `depth = y_clamped_gradient(from_y −64 → 1.875, to_y 320 → −1.125)`, which is `(176 − y) / 128`.

## 6. Hazards

### 6.1 The model, in the existing mechanisms [read: `PlanetHazards`, `HazardOrderRules`, `RadiationRules`, `OxygenManager`]

Facts the design rests on:

1. A position's hazards are the union of: weather radiation, the biome tags `hazard/radiation|heat|cold`, and
   the planet's **trait hazard, which applies everywhere on the planet and cannot be switched off by a biome**.
2. Cold is *frigid* (Cryo suit only) when the planet band is `FRIGID` **or** the biome is tagged `hazard/cold`.
   Otherwise any Tier 2 class suit keeps it out.
3. A hazard only matters while the player is exposed (not in a breathable zone). It multiplies oxygen drain by 4.
   `RADIATION` additionally damages every 40 ticks by `RadiationRules.damageFor(radiationLevel)`: 0 below level 2,
   1 at level 2, 2 at level 3.
4. `radiationLevel` = the trait value (or a biome override by id string), minus 1 with a
   `#nerospace:radiation_shade` block in the three cells above the head, plus weather when the position is open
   to the sky and outside an oxygen field.
5. A positional cold shield exists (a flaring Dawnband on Nyxara) and keeps out any cold, frigid or not.

Mapping D20 onto that:

| D20 asks | Mechanism | New data / code |
|---|---|---|
| No oxygen | `airless = true` | none |
| Cold at the top of the scale on the surface | trait `COLD` + the four surface biomes in `hazard/cold` → frigid | tag entries |
| Under the ice cold is milder | trait `COLD` with band **`COLD`** (not `FRIGID`) and no cold tag on `europa_shell`, `europa_abyss`, `europa_vent_fields` → Tier 2 class suit is enough | none. This is why the band is `COLD`: with `FRIGID` the whole moon would need Cryo and "milder" could not be expressed (Q2) |
| Near a vent cold is off | positional shield: an **active** `hydrothermal_vent` within 5 blocks, or `vent_basalt` with `DISTANCE ≤ 3` within 2 | delta A, `E/EuropaWarmth`, `VentWarmthRules`, `ConductRules` |
| Radiation on the open surface | trait `radiation = 2` + the four surface biomes in `hazard/radiation` | tag entries |
| Shielded by ice overhead, existing rule | the solid ice blocks join `#nerospace:radiation_shade`; level 2 → 1, below the damage threshold | tag entries only; `RadShadeRules` untouched; the lookup `NyxaraCrystalHazards.shaded` is already called for every planet from `PlanetHazards.radiationLevel` |
| Under the ice radiation is zero | `RadiationRules.base` returns 0 for the shell and ocean biome ids | delta B |

`E/EuropaWarmth.shieldedFromCold(ServerLevel, BlockPos)`:

- returns false at once when the level is not Europa;
- scans the sphere of radius 5 around the position (515 cells, loaded chunks only, stops at the first hit) for a
  `hydrothermal_vent` with `ACTIVE`, testing `VentWarmthRules.shielded(true, distance)`;
- in the same pass accepts a `vent_basalt` with `ConductRules.warm(distance)` when it is within 2 blocks;
- is only called when cold would otherwise bite (that is how `PlanetHazards.at(level, pos, player)` already calls
  the Nyxara one), on the 10-tick oxygen check.

A vent is `ACTIVE` only with water or `brine` directly above it. At the surface, sky-exposed water freezes
(biome temperature 0.0) and brine does not, so a surface base heats itself with a vent under a brine pool. Under
the ice any water does.

### 7.2 Two events on one planet: the minimal additive change (delta C)

Today `PlanetDefinition` carries one `WeatherParams`, and `WeatherMachine.step` takes the event from the params
it is given. The machine and its saved state already store the active event by name, so the machine does not
change at all.

```java
// PlanetDefinition
private final WeatherParams secondaryWeather;                 // Spec default: WeatherParams.NONE
public WeatherParams secondaryWeather() { … }
/** Per-event start gate. Default delegates to the existing single-argument method. */
public boolean weatherMayStart(WeatherEvent event, double phase) { return weatherMayStart(phase); }
// Spec
public Spec alsoWeather(WeatherParams params) { this.secondaryWeather = params; return this; }
```

```java
// world/planet/WeatherPickRules (pure, new)
/** Which params the next start roll uses: the primary unless a secondary exists and the roll picks it. */
public static WeatherParams pick(WeatherParams primary, WeatherParams secondary,
        boolean primaryMayStart, boolean secondaryMayStart, double roll);
/** The params that own an active event (for duration, cooldown and forceClear). */
public static WeatherParams owner(WeatherParams primary, WeatherParams secondary, WeatherEvent active);
```

Pick rule: weight each startable event by `1 / meanIntervalTicks`; with only one startable, take it; with none,
return the primary (the machine's own `mayStart` flag then blocks the start). `roll` is one extra
`level.getRandom().nextDouble()` drawn in `PlanetWeather.stepLevel` only while the machine is `CLEAR` with its
cooldown at 0.

`PlanetWeather.stepLevel` change: `WeatherParams p = m.active() ? owner(...) : pick(...)`, then
`m.step(scaled(p), enabled, mayStartFor(p.event()), random)`. `PlanetWeather.params(planet)` keeps returning the
primary, so `start`, `startAtPeak`, `clear`, the gallery and the `/nerospace` weather command behave as before
and start the plume fall. An optional event argument on the command is a nicety, not needed.

`EuropaPlanet` overrides `weatherMayStart(WeatherEvent, double)`: `FLARE` only inside `TAIL_START..TAIL_END`,
`DIAMOND_DUST` always.

`WeatherPickRulesTest`: a planet with no secondary always returns its primary (so six existing planets are
provably unaffected); weights follow the intervals over 10 000 seeded rolls; `owner` returns the secondary for
its event and the primary for anything else, including `NONE`.

Cost: one extra random draw per second per level while clear. Saved data: unchanged.

Why these numbers work with the renderer as written [read: `SkyScene.bodyAnglesInto`, `addSolid`, `eclipseLight`]:

- A sun with `orbitPeriodDays` 1 and `inclination` 25 culminates at phase 0.25, due south (yaw 0), at
  `90 − 25 = 65°`. Jupiter is pinned at exactly yaw 0, pitch 65, so the sun passes behind its centre at noon.
- Suns are drawn before bodies, so Jupiter covers the sun during the pass with no extra code.
- The sun moves 360° per day, so it spends about `24 / 360 = 0.067` of a day behind a 24° disc: the eclipse
  window 0.215..0.285. `EuropaPlanet.ECLIPSE_START/END` must match (a test should read both and compare).
- `nightShade` gives Jupiter real phases against the sun: new at noon (the dark disc that hides the sun), full at
  midnight, which is what a tidally locked moon sees. `earthshine` 0.35 reuses Luna's field (Luna's Earth has 0.6) as
  Jupiter-shine; how the renderer applies it was not read **[verify]**.
- Io and Ganymede share the sun's inclination, so they cross Jupiter's face. Moons are drawn after bodies, so
  they pass in front. Their periods are their real periods relative to Europa's sky, rounded (0.99 and 1.985
  Europa days). Real Io never strays far from Jupiter in Europa's sky; here it crosses the whole sky because D17
  asks for bodies that cross.
- Jupiter is 24°, twice its true 12°. At 12° it reads small in a Minecraft field of view; the mock-up
  `europa_sky_mock.png` uses about this proportion.
- `skybox` in the dimension type stays `"overworld"` like every other planet; the shader work in this release
  (survey section 3) treats Europa like the rest.

### 8.2 What the locked look needs that the codec does not have

| Asked for | Supported today? | Gap |
|---|---|---|
| Jupiter fixed in the sky | Yes, `fixedAngle` | — |
| Phases | Yes, `nightShade` + the 16-frame terminator sheet | — |
| Daily eclipse when the sun passes behind it | Yes: draw order + `eclipse` window + `visibility.eclipse` decal | The `corona` and `diamondRing` sub-records draw around the **sun**; left out on purpose (the sun is tiny). The ring is a decal around Jupiter instead |
| Io and Ganymede crossing | Yes, `moons` | — |
| **Slowly drifting cloud bands and a storm spot** | **No.** A body is one static texture. `terminatorScroll` exists but it *rolls the whole quad* like a wheel, which is wrong for band drift | one additive record, below |

Minimal additive change (only if the owner wants the drift; Q4). `SkyProfile.Body` has 15 fields and the codec
group limit is 16, so exactly one optional field fits:

```java
/** A baked rotation sheet: <texture>_00 … _NN, one full loop every periodTicks, neighbours cross-faded. */
public record Rotation(int frames, int periodTicks) {
    static final Codec<Rotation> CODEC = RecordCodecBuilder.create(i -> i.group(
            Codec.INT.optionalFieldOf("frames", 1).forGetter(Rotation::frames),
            Codec.INT.optionalFieldOf("periodTicks", 24_000).forGetter(Rotation::periodTicks)
    ).apply(i, Rotation::new));
}
// Body: … float earthshine, Optional<Rotation> rotation   (16th field; absent = today's behaviour)
```

`SkyScene.addSolid`: when `rotation` is present and `frames > 1`, compute
`f = frac(timeTicks / periodTicks) · frames`, draw frame `floor(f)` at full alpha and frame `floor(f) + 1`
(wrapped) at alpha `frac(f)` in place of the single body quad. Game time, like the aurora, so it never jumps
when the clock is set. Two quads instead of one; no shader, no new pipeline (the survey's Iris finding stands:
only vanilla sky pipelines are used).

JSON then becomes `"texture": "nerospace:textures/sky/jupiter", "rotation": { "frames": 32, "periodTicks": 48000 }`
with textures `jupiter_00.png … jupiter_31.png` (128×128, about 20 KB each). The generator already bakes a
closed loop: each band drifts a whole number of turns over the 32 frames, alternating direction, and the spot
rides its band. The contact sheet `europa_sky_contact.png` shows frames 0, 4, … 28 of that loop.

Without the change Europa ships a single `jupiter.png`: fixed, phased, eclipsing, but with still clouds. D17
names the drift, so the recommendation is to take the change.

`SkyAssetsTest` must learn the frame-sheet naming if the change is taken (it already knows `terminator_00…15`).

Prototype of `gas_giant`, written against the tool's own helpers (`sphere`, `noise_space`, `volume_fbm`,
`hexc`, `to_image`) and used unchanged to render the concept sheet:

```python
JUPITER_BANDS = ["#C9B08A", "#E8DCC4", "#B4875E", "#F0E6D2", "#A8704A", "#E2D2B4", "#8E6A50", "#D8C8A8", "#B89A78"]

def gas_giant(name, size, frame=0, frames=32, bands=JUPITER_BANDS, spot="#B5502E"):
    radius = 0.92
    x, y, z, r = sphere(size, radius)
    lat = np.arcsin(np.clip(y, -1, 1))
    lon = np.arctan2(x, z)
    sample = noise_space(name)
    t = frame / float(frames)
    band_f = (lat / np.pi + 0.5) * (len(bands) - 1)
    k = np.clip(np.round(band_f).astype(int), 0, len(bands) - 1)
    drift = np.where(k % 2 == 0, 1.0, -1.0) * 2 * np.pi * t          # closed loop: one turn per band
    L = lon + drift
    cx, cz = np.cos(L), np.sin(L)
    warp = volume_fbm(sample, cx * 6 + 9, lat * 14, cz * 6 + 9, 5) - 0.5
    bf = np.clip(band_f + warp * 1.1, 0, len(bands) - 1.001)
    i0 = np.floor(bf).astype(int)
    f = (bf - i0)[..., None]
    pal = np.stack([hexc(c) for c in bands])
    rgb = pal[i0] * (1 - f) + pal[i0 + 1] * f
    rgb = rgb * (0.86 + 0.28 * volume_fbm(sample, cx * 18, lat * 40, cz * 18, 4)[..., None])
    spot_lon = -0.6 - 2 * np.pi * t
    d_lon = np.arctan2(np.sin(lon - spot_lon), np.cos(lon - spot_lon))
    d = np.sqrt((d_lon / 0.34) ** 2 + ((lat - 0.38) / 0.14) ** 2)
    m = np.clip(1 - d, 0, 1)[..., None] ** 0.7
    rgb = rgb * (1 - m) + hexc(spot) * m
    rgb = rgb * (0.35 + 0.65 * np.clip(z, 0, 1) ** 0.6)[..., None]   # limb darkening
    return to_image(rgb, np.clip((radius - r) * size / 2, 0, 1))
```

Known flaw of the prototype: the band index flips sign of drift at band edges, which shears the turbulence where
two bands meet. That is what real zonal jets look like at a distance, but the builder should look at the 32
frames in sequence before committing them.

Appended after `OPEN_WATER_SPRING`. Read in one place, the stage-3 column pass of `TerraformConversion`: when
the table has the rule and the column's top block is this table's `surfaceTop`, the top block and the
`OPEN_OCEAN_DEPTH = 3` blocks under it become `liquid` source blocks, provided each is `surfaceTop`,
`surfaceSub` or in `extraSurface` (so player builds, ores and machines are never eaten). Any `penitente_blade`
or snow layer above the column is removed. It is one more write of at most four cells in a pass that already
writes four, under the same per-pulse column budget.

Pure helper `OpenOceanRules.cells(columnTopIsSurfaceTop, convertibleRunLength)` → 0..4, with a test.

Fauna in water **[verify]**: `TerraformFauna` seeds the stage-3 herd; I did not read whether it only places on
solid ground. If it does, give it a branch for a species whose spawn-placement type is in-water: pick a water
cell in the converted column. The biome spawner (5.6) populates the sea either way, so the herd seeding is the
only part at risk.

### 10.3 Breathability: the conflict, flagged (Q1)

In the existing system a terraformed chunk is permanently breathable (`OxygenManager.isBreathable`: the
terraformed-chunk flag, and any overlay at stage ≥ 1), and gravity there becomes 1.0. D24 says Europa's end state
is **not** a breathable world. Those two cannot both hold without a change.

Proposed: `Rule.NO_ATMOSPHERE` (delta G). `isBreathable` skips its two terraform branches when the level's
planet has a table with this rule. Oxygen fields, pads and external pressure still work, so bases are unaffected.
Europa's hazards then continue to apply on terraformed ground, softened by the biome change (6.2).

If the owner prefers no change to the oxygen rules, drop the rule from the table: terraformed Europa is then
breathable from stage 1 like every other world and hazards stop biting there, and the wiki describes the haze as
thin but breathable. The table and the rest of this section are otherwise identical.

## 11. Easter egg: europium

The joke is the name. Europium is a real rare-earth element named after Europe; the red phosphor in old colour
television tubes was a europium compound. So Europa hides a little europium, and all it does is glow red.

| Piece | Spec |
|---|---|
| Ore | `nerospace:europium_ore`, plain `Block`, in `vent_basalt`, light 2. Only in `europa_vent_fields`, `rarity_filter` 6, vein size 3, Y −64..−30 (rarer and deeper than anything else; Luna's joke ore is chance 4, size 4) |
| Item | `nerospace:raw_europium`; tooltip line `item.nerospace.raw_europium.tooltip`: "Named for the wrong Europa." |
| Block | `nerospace:europium_lamp`: 2×2 `raw_europium` → 1. Toggles red light 14 / 0 on use (`PhosphorRules`). Decoration only |

| Star Guide | `hiddenStep("rare_earth", raw_europium, "europa/rare_earth")`, last in `worlds_europa` |
| Harmless | no hazard, no machine input, no trade, no quest objective, no trophy hook, not in any `c:` ore tag that a processing mod would pick up **except** `c:ores/europium` (Q9) |

Isolation, in the pattern of `T/world/planet/luna/CheeseIsolationTest`: new

  - `worldgen/configured_feature/europa_europium_ore.json`, `R263/…/feature/europa_europium_ore.json`,
    `worldgen/placed_feature/europa_europium_ore_placed.json`
