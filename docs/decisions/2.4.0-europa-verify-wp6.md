## Area 1 — sky codec compatibility (checked)

- `SkyProfile.Body` codec group (`common/src/main/java/za/co/neroland/nerospace/client/sky/SkyProfile.java:179-196`)
  has exactly 16 fields (id … earthshine, rotation): at DFU's `P16` limit, not over. `Aurora` already used `P16`
  in 2.3, so every cell's DFU supports it.
- Constant-pool comparison of the compiled `SkyProfile$Body`, `Background`, `Fog`, `Stars`, `Glow`, `HorizonGlow`,
  `NightShade`, `FixedAngle` and `SkyProfile` classes between `nerospace-neoforge-26.3-2.3.1.jar` and
  `-2.4.0-beta.1.jar`: the only differences are the 16th field (`rotation`, `P16`/`Function16`, the new
  `Rotation` class). No string, float or int default changed, so the seven pre-existing profiles and any 2.3-shaped
  resource-pack profile decode to the same values.
- The seven pre-existing `sky/*.json` files are byte-identical to the 2.3.1 jar's copies; only `europa.json`
  gains `rotation` (`{"texture": "nerospace:textures/sky/jupiter", "frames": 32, "periodTicks": 24000}`, as specified).
- 15-argument constructor (`SkyProfile.java:170-176`) delegates with `Optional.empty()`; the 10-argument one still
  chains to it.
- `Rotation.texture` required inside the object (`SkyProfile.java:212`); `frames` 1 / `periodTicks` 24_000 defaults
  (`SkyProfile.java:208-214`) match amendments section 7 WP6.
- Frame maths (`SkyScene.java:1044-1098`): `periodTicks <= 0` and `frames <= 1` short-circuit before any division
  (`rotationPosition`, `rotates`); negative time handled by `frac = v - floor(v)` (`SkyScene.java:1600`); index
  clamped in `rotationFrameA` and `rotationTexture`; `% Math.max(1, frames)` never divides by zero. Lite quality
  draws the still (`rotates` returns false). NaN time would give NaN alpha (see V6-01, NOTE only; time is game
  time plus partial tick and cannot be NaN).
- Loop seam: `rotationFrameB(31.x) = 0`, tested (`SkyRotationTest.frameMaths`), and the 1-tick continuity sweep
  over a full period is tested. Closure frame 32 == frame 0 is asserted in `tools/test_sky_textures.py` (per the
  status file; re-run under area 6).
- Frames: 32 `textures/sky/jupiter_NN.png` and 32 `textures/sky/square/jupiter_NN.png` exist, plus both stills.
  `SkyRotationTest.framesExist` checks the same from the profile.
- Draw path: `addSolid` (`SkyScene.java:984-998`) adds one or two ordinary translucent `Quad`s from the growable
  pool (`SkyScene.java:580-590`); `PlanetSkyDraw` draws every quad generically and resolves square variants per
  texture through `styled` (`PlanetSkyDraw.java:230-245`), so it needed no change. The 1.21.1 2.4.0 jar contains
  the `Rotation` class and the 32 globe frames.
